# 后台增量汇总与可重建进度快照

状态：accepted；2026-10-20 架构改进。

Web 执行器按配置周期消费运行任务的新证据，维护文件身份、长度、末段校验和日志游标；详情请求只读带时间戳的快照。任务状态变化会重新汇总，已完成任务按不可变执行结果处理。相同调用标识去重，未知用量和乱序完成页保留原有语义。

索引与快照是派生数据，可以从原始日志、TeX 和报告重建，不修改阶段状态库或完成账本。采用任务级锁和原子写入，先写快照再提交游标，允许中断后幂等重放。日志截断、轮换、尾部半条 JSON 和索引损坏均有恢复路径；没有快照或快照过期时网页明确提示。

选择后台投影是为了让多个查看者共享扫描和聚合成本，而不是把每次 HTTP 请求变成全量文件扫描。代价是最多一个采集周期的可见延迟及可重建的索引状态；单进程内仅保留有限数量的已解析投影缓存。

证据：原设计 `4bbc09f` 的 `docs/WEB_DESIGN.md` 已要求增量汇总；实现 `0682e83`，当前 `web/backend/observations.py`、`worker.py`、`api.py` 和 `web/tests/test_observation_projection.py`。
