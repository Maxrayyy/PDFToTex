# 文字越界、嵌套框尺寸与布局重试

记录日期：2026-10-03。状态：通用框尺寸修复已完成，历史文档重放及容器验证见下文。

## 现象与根因

XeLaTeX 返回 0 不代表文字全部位于纸张内。OCR 输出的负位移、不可断行 URL、同段落的表格与落款、固定高度框、嵌套缩放和旋转都可能让文字超出纸张。队列在布局验收时退出，是阻止有裁切的结果发布；反复重启同一份未修复的输入不能解决问题。

共同根因是缺少统一的父级尺寸约束：表格在内层模式绕过外层限高；变换之前能容纳的内容在缩放或旋转后可能超出所在栏宽；正文换行并不等于 TeX 段落结束。此前布局重试只处理第一个失败源页，多页同时失败会耗尽全局尝试次数。

## 已尝试方法及局限

1. 只检查编译退出码：不能检测纸外字形，现增加 PDF 字形边界验收。
2. 将所有页数变化判失败：与允许多页的需求冲突。分页差异单独记录，纸外字形及错误纸张尺寸才阻止导出。
3. 全局缩字号或缩间距：不能修复绝对位移、同段落、不可断 URL 和变换后的框；保留为有界的后备手段。
4. 逐个环境加补丁：遗漏 tabular*、scalebox 和内层变换；现统一框尺寸入口，变换完成后按父级空间约束。
5. 单页重试：后续坏页得不到机会。现每次调整所有越界源页，仍保持最多 3 次编译。
6. 将已转义 URL 直接送入 url：会显示多余反斜杠。使用 LexoidTextUrl 展开安全标点后再断行。
7. 仅匹配表格后 noindent：先后遗漏字号声明及普通文字。扩展段落分隔处理，同时屏蔽注释与 verbatim。
8. 用 let 保存 parbox：在当前 LaTeX 中引发递归并耗尽 TeX 容量；改用 NewCommandCopy，真实编译回归通过。
9. 仅重启：缓存或旧镜像仍包含相同错误。恢复时需确认运行镜像和失败阶段，保留识别缓存，且先发重启邮件。

## 当前通用修复

- `page_layout.py` 通过 LexoidFitContent 为 resizebox、rotatebox、scalebox 和 parbox 提供共同入口；tabular、tabular*、minipage 使用同一约束。内层以当前 linewidth 限宽，外层还受可用高度限制。
- 固定高度框须先报告真实内容高度；不通过裁切框内容来消除检测错误。
- `cli.py` 将实际越界输出页映射回源页，一轮调整全部仍有调整空间的源页。
- `inspect_layout` 输出方向、数量、最大距离、源页映射及最多 8 个字形样本。沿用 1bp 容差。
- `export_ok` 表示没有纸外字形且纸张尺寸正确；`ok` 保留更严格的分页检查。多页可通过 export_ok。
- OCR 提示词要求按当前栏宽排版、显式结束表格段落、长单元格可断行、URL 字符完整，不用负偏移模仿扫描件裁切。

## 2026-10-03 下午：结束标记漂移造成尺寸误报

U3 `pdftotex-u3-a33z2202411017-001` 的 `MX-C4081R_20260806_103001.pdf` 编译退出 6。48 个源页生成 49 页，纸外字形为零，但报告输出第 5、7 页尺寸错误。源第 4、6 页的结束标记分别落入下一个竖版源页，与下一页开始标记重叠。

根因是 TeX 延迟 write 节点：满页最后的 center 结束后，结束标记可留在贡献列表中，直到下一源页 shipout 才写入，从而把下一源页错误地归入前一个横版源页。单纯缩字号无关，也不能取消纸张尺寸校验来掩盖错误。

修复 LexoidPageEnd：先在当前源页几何设置下 clearpage 完成内容输出，再 immediate write 记录已输出的绝对页码，最后关闭组。新增四种接近满页高度的横竖切换测试，其中满高场景在旧代码上复现尺寸误判；修复后全部 50 项布局测试通过。整份文档重放成功，修复前后 49 页的逐页尺寸与提取文字完全一致。证据目录：`data/audits/page-mark-before-20261003/` 和 `data/audits/page-mark-after-20261003/`。

同日 16:42，U1 的 `MX-C4081R_20260806_163207.pdf` 也因同类错误退出：162 源页，无纸外文字，报告输出第 15 页尺寸错误。同一修复后整文档重放通过，生成 163 页，越界和尺寸错误均为空；证据位于 `data/audits/page-mark-u1-20261003/`。

## 2026-10-03 傍晚：填充线后的负间距

U3 `MX-C4081R_20260806_103456.pdf`（61 源页）在源/输出第 36 页有 11 个点字形超出右边界，最大 42.073bp。问题结构是 `\noindent\dotfill\hspace{-5cm}` 后跟手写签名：负间距减少行宽计算中的自然宽度，导致点线被伸长到纸外；它不位于行首，因此先前仅修复行首负位移的规则没有覆盖。缩间距与缩字号两次重试仍然失败。

通用修复扩展至 dotfill、hrulefill、hfill 后的负物理水平位移，将其归零，保留填充线和后续文字，不改普通行内字距或正间距，继续屏蔽注释与 verbatim。最小编译回归在旧实现上复现 11 个点字形越界，修复后全部 51 项布局测试通过；完整 61 页重放成功，仍为 61 输出页，无越界或尺寸错误。证据：`data/audits/leader-20261003/summary.json`。
