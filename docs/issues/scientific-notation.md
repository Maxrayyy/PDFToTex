# 科学计数法与数学模式边界

## 2026-10-03：换行间距误判为数学模式

U1 `pdftotex-u1-a35p202409001-001` 处理 `MX-C4081R_20260806_163553.pdf`（77 页）时 optimise 退出 6。第 77 源页表头 `(p/m^{3})` 报 Missing $ inserted，编译停止在第 84 输出页，尚未进入 PDF 布局验收；这次不是字形越界。

根因：正文较早的标题换行 `\\[1em]` / `\\[0.5em]` 被数学边界正则从第二个反斜杠识别为 `\[`。数学状态持续污染后续内容，既漏修正文裸上标，也可能把真正数学表达式的上标改成普通字符。单字符负向回看同样会把双反斜杠后的 `$` 错当转义。

修复：数学符号修复器和上标修复器均先完整消费 TeX 控制词、控制符，再识别真正的数学分隔符；不从命令中间开始匹配。两个最小回归在旧代码上失败，修复后通过并验证重复应用结果不变。原失败优化输入进行确定性上标修复（7 处）后，完整 77 页重放通过，生成 85 页，无纸外字形和尺寸错误；证据在服务器 `data/audits/caret-20261003/`。

尝试记录：仅重放排版规则不能修复 Missing $；直接对完整 normalize_tex 要求幂等的审计脚本发现其他规范化步骤仍会变化，因此本次重放使用目标上标修复器并验证其幂等性。旧测试镜像内还有 `/tests/pipeline/texopt` 源码副本，只挂载 `/src/texopt` 不保证测试使用新实现；最终重建镜像后 488 项 pipeline 测试及 3 个子测试、146 项 Lexoid 测试通过。U1 在保留识别与协调缓存的情况下恢复优化，原失败文件已完成并进入后续文件。

## 现象

识别结果中的 `1.04\\times10^{7}`、`4\\times10^{7}/a` 等表达式被拆到文本模式和数学模式之间，XeLaTeX 报 `Missing $ inserted`，或上标位置错误。

## 已尝试方案

- 只给孤立的 `\\times`、`\\div` 加数学模式：指数仍留在文本模式，错误未消失。
- 只匹配带空格的 `\\times 10`：OCR 常见的紧凑写法无法命中。
- 对整页或整行强制包 `$...$`：会把单位、字段宏和普通文字误放进数学模式，破坏原有版式。
- 让语法模型重写整段 TeX：模型可能同时改动字段括号和表格边界，产生新的结构错误。

## 当前方案

在确定性规范化阶段识别“数字 + 运算符 + 数字 + 指数/后缀”的最小表达式，统一放入 `\\ensuremath{...}`；只处理生成的 TeX，不修改 PDF。对已在 `\\ensuremath` 内的表达式跳过二次包装，避免嵌套。

## 为什么仍可能失败

模型可能把数学表达式拆成多个字段宏，或输出不完整的大括号；正则无法可靠推断跨宏语义。此时应保留原始识别结果并升级整页视觉识别，不能继续叠加修复。

## 验证

单元测试覆盖紧凑科学计数法、嵌套 `\\ensuremath`、字段后的运算符和上标；最终以双遍 XeLaTeX 编译为准。

### 缓存处置教训

不要仅删除最后一个 `$` 后直接发布旧优化稿。旧规范化缓存可能已经把段落空行改成 `%`，
即使可以编译，也会把标题、表格与签名挤在同一行。
必须保留识别草稿，从草稿重新生成受影响页的规范化及后续产物，不能凭猜测把所有 `%` 改回空行。
